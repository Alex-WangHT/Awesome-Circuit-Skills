# 电路架构与 PCB 前期资料

以用户的需求文档、已选器件和目标 EDA 工程为依据，帮助用户完成“功能与选型 → 模块供电及总线 → Power Tree → 便于 PCB 布线的 Block Diagram → 总线与主控逐信号 Pinlist”。将这三份成果作为 PCB 设计资料的第一部分，保存到用户指定的工程位置；若尚无工程，则交付可编辑的文档、图和表，并说明如何纳入工程。不要把架构图当作已完成布线的 PCB 或电气原理图。

## 分析需求和选型

1. 读取需求文档，列出功能、性能、外部接口、供电输入、环境与机械限制，以及已有器件或必须遵守的设计约束。给每项需求保留出处；区分已确认条件、估算和待确认项。
2. 按功能划分主控（CPU、SoC、FPGA、MCU 等）、电源、存储、传感、通信、连接器等模块。为每个模块记录输入输出、与其他模块的接口、供电需求及其对应需求。
3. 帮助用户选型：先检查主控和关键器件的功能资源、接口数量与速率、IO 电压域、供电和功耗、封装与可布线性，再比较候选器件的成本、供货、生命周期及资料完整性。列出候选、取舍理由、完整料号与封装；已有指定器件时先验证其适配性，不擅自替换。关键引脚、额定值和配置条件须有对应型号 datasheet 或厂家资料依据。资料不足时标记“待确认”，不要编造物理脚号。

## 建立模块、电源和总线关系

4. 先为**每个模块**列出所需电源轨、电压及容差、峰值和典型电流、噪声敏感度、上电/掉电时序，并列出引出的总线和其他信号：端点、方向、信号组、速率、IO 电平、时钟、复位与特殊布线约束。共享总线要列出所有端点。
5. 根据模块供电要求画 Power Tree：从外部输入经过保护与电源变换到各电源轨，再到实际负载；标注轨电压、预估电流、转换器候选、时序和需要隔离或低噪声的负载。核对电源容量、器件推荐工作条件、IO 域和接口电平，不以器件绝对最大额定值充当工作条件。
6. 根据总线和主控的关系画 Block Diagram。主控置于逻辑中心，连接器朝预期板边，相关功能块成组；让高速、差分、时钟和敏感模拟路径尽量短，减少跨区和交叉，同时考虑电源流向、热源与噪声隔离。用“靠近、同侧、远离、板边”等相对方位表达布局意图；未获板框和封装尺寸时不要虚构精确坐标。图中标出模块、所选器件、接口/总线、电源域与主要信号方向。

## 逐信号 Pinlist

7. 在功能、选型及接口说明明确后，为每条总线的**每根信号**建立一行映射：总线/接口名、信号名和方向、外设模块与功能脚/物理脚、主控外设实例与功能脚/物理脚、IO Bank/电压域、状态、依据和备注。多端点总线逐端点列出；差分对保留 P/N 配对，地址/数据总线保留位序。物理脚未核实时保留逻辑功能并标记“拟分配”。
8. 逐项对照器件资料核验主控复用功能、专用脚、启动/调试脚、IO Bank 电压、时钟能力、差分配对和封装脚位。检查同一物理脚重复分配、总线缺线或多线、信号方向/电平冲突，以及 Pinlist 与 Block Diagram、Power Tree 的模块和接口名称是否一致。只有核对完整料号和封装的资料后，才将物理脚标记“已确认”。

## 交付

交付选型与假设记录，以及可编辑的 Block Diagram、Power Tree、Pinlist；注明需求文档和 datasheet 版本/页码、待确认事项与后续原理图/PCB 设计约束。用户指定 EDA 或项目格式时优先放入该工程可管理的文件；没有指定时可使用 Markdown/Mermaid 绘图和 CSV/表格。此阶段的成果用于后续 `circuit-schematic` 绘制和检查；缺失的器件符号、封装或 3D 模型交给 `circuit-library` 工作流。
